Guía docente · Restauración de fotografías con autoencoders

Sesión 42 · 120 minutos

Propósito

La sesión usa restauración de imágenes CIFAR-10 para conectar el objetivo de reconstrucción con una arquitectura convolucional, un protocolo experimental y una decisión sobre el cuello de botella. El resultado esperado no es obtener fotografías perfectas, sino explicar qué aprende el modelo y reconocer dónde falla.

Preparación antes de clase

  1. Abra el notebook en Google Colab y seleccione un acelerador GPU.
  2. Ejecute una vez el modelo base con QUICK_MODE = False y confirme que la descarga de CIFAR-10 funciona.
  3. Conserve abierta la tabla de métricas y una rejilla de reconstrucciones para la contingencia de conectividad.
  4. Divida el curso en parejas. Asigne 16 canales a la mitad y 64 canales a la otra mitad.
  5. Comparta el taller labs/semana-16-autoencoders.qmd.

Bloque 1 · Contexto y predicción

Muestre primero imágenes limpias y dañadas. Pregunte qué daños podrían revertirse y cuáles destruyen información.

Respuesta esperada: el ruido leve conserva estructura local. Una oclusión elimina píxeles y obliga al modelo a inferir contenido a partir de regularidades aprendidas. La inferencia puede ser plausible sin coincidir con el original.

No presente todavía la arquitectura. El objetivo es separar restauración de recuperación exacta.

Bloque 2 · Mecanismo

Mantenga en el tablero estas relaciones:

\[ z=f_\theta(\tilde{x}),\qquad \hat{x}=g_\phi(z),\qquad \mathcal{L}=MSE(x,\hat{x}). \]

Pregunte qué ocurriría si el objetivo también fuera \(\tilde{x}\).

Respuesta esperada: la red recibiría incentivos para reproducir el ruido. El entrenamiento con eliminación de ruido exige entrada corrupta y objetivo limpio.

Pregunte por qué una identidad perfecta no garantiza una representación útil.

Respuesta esperada: una red con capacidad suficiente puede copiar sin priorizar estructura. El cuello de botella y la corrupción restringen la solución, aunque no garantizan semántica.

Bloque 3 · Arquitectura y dimensiones

Recorra el encoder en este orden:

Frontera Shape
Imagen \(32\times32\times3\)
Conv 1 \(16\times16\times32\)
Conv 2 \(8\times8\times64\)
Conv 3 \(4\times4\times128\)
Cuello \(4\times4\times32\)

Calcule con el grupo \(32\cdot32\cdot3=3.072\), \(4\cdot4\cdot32=512\) y la razón nominal \(3072/512=6\). Aclare que esta razón cuenta activaciones, no equivale a un formato de compresión de archivos ni incluye el costo de almacenar el modelo.

Bloque 4 · Demo del modelo base

Ejecute las celdas hasta la evaluación. Antes de mostrar resultados, solicite dos predicciones:

  1. ¿El modelo superará a la entrada dañada en PSNR y SSIM?
  2. ¿Qué regiones perderán más detalle?

Interprete las métricas juntas:

  • MSE menor indica menor error cuadrático promedio.
  • PSNR mayor indica menor distorsión pixel a pixel en la escala fijada.
  • SSIM mayor indica mayor similitud estructural local.

Punto docente: una mejora promedio puede coexistir con fallas importantes. Revise imágenes individuales y el mapa de error absoluto.

Bloque 5 · Mini-reto

Asigne una sola variante a cada pareja para conservar tiempo. Todas las parejas usan la misma semilla, partición, ruido, pérdida, optimizador y máximo de épocas.

Grupo Canales Código Compresión nominal
A 16 256 12:1
B 64 1.024 3:1

Pida que copien sus resultados a una tabla colectiva. No permita declarar una variante ganadora solo por MSE. La recomendación debe considerar PSNR, SSIM, parámetros, tiempo y fallas visuales.

Patrón esperado, no resultado garantizado: el cuello amplio suele conservar más detalle, mientras el pequeño impone mayor compresión. Las diferencias exactas dependen de inicialización, entrenamiento y hardware.

Bloque 6 · Oclusión no vista

Antes de ejecutar, recuerde que el entrenamiento solo usó ruido gaussiano. La oclusión central constituye un cambio del proceso de corrupción.

Respuesta esperada: el modelo puede suavizar o rellenar la región con patrones frecuentes, pero no dispone de información suficiente para recuperar el contenido exacto. Una posible mejora en la zona no demuestra que haya reconstruido el objeto original.

Use este bloque para introducir la pregunta de despliegue: ¿la corrupción de producción coincide con la simulada durante el entrenamiento?

Errores frecuentes

Error Corrección
Entrenar con dañada como entrada y objetivo Usar imagen limpia como objetivo
Ajustar decisiones con test Usar validación y abrir test al final
Comparar variantes con ruidos distintos Reutilizar las mismas matrices corruptas
Interpretar PSNR como calidad perceptual completa Revisar también SSIM y casos visuales
Llamar generativo al autoencoder determinista Limitar la afirmación a reconstrucción condicionada
Confundir 6:1 con tamaño de archivo Aclarar que cuenta valores latentes

Contingencias

Sin GPU

Active QUICK_MODE = True. El notebook usará 12.000 imágenes de entrenamiento, 3.000 de validación, 2.000 de prueba y tres épocas. Presente los valores como evidencia rápida, no como comparación definitiva.

Sin conexión para descargar CIFAR-10

Use la ejecución abierta antes de clase para explicar resultados. El grupo puede completar predicciones, libro de dimensiones y análisis de fallas sin volver a entrenar.

Entrenamiento lento durante el mini-reto

Cada pareja ejecuta una sola variante. Recoja al menos dos resultados por variante y discuta variabilidad en lugar de esperar a todo el curso.

Criterios de una buena salida

La conclusión final debe:

  • nombrar la variante recomendada;
  • citar al menos dos métricas y una observación visual;
  • reconocer el costo o la compresión sacrificada;
  • describir una falla;
  • limitar la recomendación al ruido y los datos evaluados.
